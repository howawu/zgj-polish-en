# Contributing

Contributions are welcome when they improve precision, consistency, or usability without making the style freer than intended.

## Guidelines

- Preserve the skill's narrow purpose: rigorous, conservative IEEE-style polishing.
- Do not add broad creative-writing or marketing-style rules.
- Prefer concrete rewrite patterns over abstract advice.
- Keep technical examples generic and non-copyrighted.
- Do not include full paragraphs from published papers.
- Keep `SKILL.md` concise; place detailed guidance in `references/style-guide.md`.
- Run validation before submitting changes:

```bash
python scripts/validate_skill.py
```

## Good Changes

- Adding a high-frequency fixed sentence pattern.
- Clarifying an ambiguous grammar or usage rule.
- Improving install instructions.
- Fixing metadata, validation, or formatting issues.

## Avoid

- Rules that encourage aggressive rewriting.
- Replacing stable technical terms with synonyms for variety.
- Adding claims, examples, or reviewer preferences that are not supported by the style guide.
- Copying copyrighted prose from papers into the repository.
